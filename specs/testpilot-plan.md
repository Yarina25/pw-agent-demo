# TestPilot Demo - Test Plan

## Application Overview

- **被测地址**：`https://s6.ink/testpilot-demo`（短链入口，实际由 Cloudflare Tunnel 承载 SPA）
- **应用类型**：中文 AI 测试全流程平台（TestPilot），单页应用（SPA），无登录鉴权，进入即为 `丁蕾 / admin` 会话
- **技术栈特征**：客户端路由（`/`、`/requirements`、`/cases`、`/runs`、`/reports`、`/defects`、`/assistant`、`/interview`、`/knowledge`、`/settings`）、原生 `<table>`、原生 `<select>`、Tailwind 风格样式、REST 接口（`/api/v1/projects/p1/...`）
- **全局布局**：
  - 左侧 `<nav>`：质量概览、需求 & AI 生成、用例库、测试执行、测试报告、缺陷管理、AI 助手、面试题库、知识库、设置
  - 顶部 `<header>`：页面标题 + 当前项目徽标（TRADE / GROW）+ 项目选择器 + 全局搜索 + 用户信息
  - 右下角悬浮 **TestPilot AI 助手**：每页都存在，含 3 个快捷提示按钮（文案与页面内容重名）
- **项目上下文**：电商交易中台（TRADE）、会员增长系统（GROW）、AI 客服助手；切换项目后徽标与执行数据联动
- **异步加载**：多个页面先渲染「正在加载…/加载中…/正在加载报告详情…/加载设置…」占位，需等待其消失再断言
- **定位器风险**：悬浮 AI 助手与页面正文存在同名按钮/输入框，页面级断言必须限定在 `main` 作用域；导航限定在 `getByRole('navigation')`；项目选择器为页面首个 `combobox`
- **路由约束**：直接访问 `https://s6.ink/testpilot-demo/runs/RUN-3080` 会被短链站点重定向到 `https://s6.ink/home`，所有用例必须从入口进入后通过侧边栏 SPA 导航
- **数据写入影响**：
  - 需求页「AI 生成用例」会持久化生成结果（需求由「待分析/尚未生成」变为「已分析/已生成 N 条用例」），重复执行时按钮变为「重新生成」，因此生成类用例需兼容两种按钮文案
  - 设置页「保存配置」会 `PUT /api/v1/projects/p1/settings/execution`，测试需改后还原
  - 执行页「发起执行」会新增执行记录，测试仅验证弹窗，不提交
  - 用例库 / 缺陷 / 报告 / 知识库 / 面试题库均为只读浏览

### Known Issues（Planner 探索发现）

1. **全局搜索无响应**：在顶部「搜索用例 / 缺陷 / 执行记录」输入关键词并回车，无下拉、无请求、无跳转、无结果提示（`/api` 无调用）。计划中以 `test.fixme` 记录期望行为，不作为失败用例重试。
2. **缺陷详情不支持 ESC 关闭**：详情面板需点击 `✕` 关闭，ESC 无反应（交互不一致，不影响功能，测试按 `✕` 编写）。

## Execution Notes（供 Generator / Healer）

- 每个用例独立从入口 `https://s6.ink/testpilot-demo` 启动，不依赖上一用例状态；禁止直接深链子路由
- 页面断言统一限定 `main`；导航用 `getByRole('navigation').getByRole('link', …)`；项目选择器用首个 `combobox`
- 异步列表断言使用 Playwright 自动重试（`expect(locator).toHaveCount(n)`），不要固定 `waitForTimeout` 作为唯一等待手段
- AI 生成用例、保存配置为写入型用例：前者兼容「AI 生成用例 / 重新生成」，后者 `try/finally` 还原并发数
- 全局搜索为已知产品缺陷，使用 `test.fixme` 并在用例内注释实际表现
- 执行顺序串行（共享 demo 数据），配置中 `workers: 1`
